# 截图翻译桌面应用设计规格

**日期：** 2026-07-27
**状态：** 已完成需求讨论，等待书面规格复核
**许可证：** MIT
**目标平台：** Windows 10/11 x64

## 1. 产品目标

构建一个面向外服游戏聊天场景的 Windows 截图翻译工具。程序启动后常驻系统托盘，用户按下全局快捷键即可冻结鼠标所在显示器、框选聊天区域，并将选区图片直接交给多模态模型翻译。翻译结果在选区旁的浮动面板中显示，用户还可以输入中文快捷回复，并将回复翻译成截图识别出的主要语言。

产品重点是翻译质量、游戏中的操作效率、稳定的 Windows 桌面交互以及简洁美观的界面，而不是提供通用 OCR 或完整翻译平台。

## 2. 首版范围

### 2.1 包含的能力

- Windows 10/11 x64 单平台支持。
- 普通窗口和无边框窗口游戏；不承诺支持独占全屏。
- 后台托盘运行、单实例启动和标准 Windows 安装包。
- 可配置的全局截图快捷键，默认 `Ctrl + Alt + D`。
- 冻结鼠标当前所在显示器；不允许跨显示器框选。
- 拖拽创建选区、移动选区以及通过四角和四边中点共八个控制点缩放选区。
- 选区变化并稳定后重新发起翻译。
- 截图直接发送给多模态模型，不经过本地 OCR。
- OpenAI 兼容接口，一套当前模型配置和一个千问默认预设。
- 默认模型 `qwen3.7-flash`，默认关闭思考模式。
- 自动识别截图主要语言，默认翻译为简体中文。
- 在截图结果面板内输入快捷回复，并默认翻译成截图识别出的主要语言。
- 复制截图译文或回复译文后关闭覆盖层并返回原窗口。
- 所有配置项均可直接在设置窗口中查看和修改，API Key 明文显示并保存在本机配置文件中。
- 跟随系统、浅色和深色设置主题；截图覆盖层始终使用高可读性的深色面板。
- MIT 开源许可证、构建说明、GitHub Actions 构建与测试。

### 2.2 明确不包含

- macOS、Linux 或移动平台。
- 独占全屏游戏兼容承诺。
- 跨显示器框选。
- 本地 OCR、离线翻译或 OCR/模型双模式。
- 独立文字翻译窗口或第二套文字翻译快捷键。
- 多套模型配置、模型自动故障切换或账号系统。
- 翻译历史、云端同步、自动更新或遥测。
- 自动向游戏聊天框注入文字；首版通过剪贴板复制后由用户粘贴。

## 3. 技术方案

应用采用 .NET 8 和 WPF。该方案直接面向 Windows，适合处理全局快捷键、系统托盘、屏幕捕获、置顶覆盖窗口、多显示器 DPI、剪贴板以及安装包等原生能力，同时不需要额外后台服务或数据库。

应用是单进程、单实例桌面程序。核心业务逻辑与 Windows API 适配分离，确保区域计算、翻译状态机、配置校验和响应解析可以独立测试。

建议的解决方案边界如下：

- `ScreenshotTranslation.App`：WPF 启动入口、托盘、设置窗口、截图覆盖窗口和依赖组装。
- `ScreenshotTranslation.Core`：选区几何、翻译用例、请求状态、模型接口、配置模型和领域错误。
- `ScreenshotTranslation.Infrastructure`：Windows 快捷键、屏幕捕获、剪贴板、开机启动、本地设置、HTTP 模型客户端和日志。
- `ScreenshotTranslation.Tests`：核心单元测试和受控的基础设施集成测试。

具体文件拆分在实施计划中确定，但每个文件应保持单一职责，避免把窗口行为、HTTP 调用和业务状态堆叠在同一个类中。

## 4. 启动与托盘行为

1. 程序使用系统互斥锁保证单实例运行。
2. 首次启动或缺少必要模型配置时打开设置窗口。
3. 配置完整后再次启动程序时直接进入托盘，不显示任务栏主窗口。
4. 再次运行可执行文件时，不创建第二个进程，而是唤起已有实例的设置窗口。
5. 左键点击托盘图标打开设置窗口。
6. 右键菜单仅包含“开始截图翻译”“设置”和“退出”。
7. “随 Windows 开机启动”是可配置项，默认关闭。

## 5. 截图翻译交互

### 5.1 进入截图状态

1. 用户按下截图快捷键。
2. 程序立即捕获鼠标所在显示器的当前画面，并保存为本次会话的不可变原始位图。
3. 程序创建覆盖该显示器的全屏置顶窗口，使用捕获位图作为背景，从而实现视觉冻结。
4. 其他显示器不冻结，也不参与本次框选。
5. 冻结画面外层添加约 55% 黑色遮罩，鼠标显示为带轻微高亮光圈的十字指针。

### 5.2 创建和调整选区

1. 按住鼠标左键拖拽创建矩形选区。
2. 选区内部显示未变暗的原始画面，外部保持遮罩。
3. 松开左键后，如果选区达到最小有效尺寸，则开始翻译；过小选区不发起请求。
4. 选区边框包含四角和四边中点共八个圆形控制点。
5. 用户可以拖动控制点缩放选区，也可以拖动选区内部移动整个选区。
6. 拖动过程中只更新视觉范围；松开鼠标、范围稳定后才重新提交翻译，避免连续产生 API 调用。
7. 新请求开始后，旧请求被取消或标记为过期。过期响应不得覆盖当前结果。

### 5.3 退出规则

以下操作关闭覆盖层并取消未完成请求：

- 按 `Esc`。
- 点击选区和结果面板之外。
- 尚未形成有效选区时单击或右键。
- 成功复制截图译文或回复译文。

关闭覆盖层后，焦点返回截图前的窗口，便于用户直接向游戏聊天框粘贴。

## 6. 翻译结果与快捷回复面板

面板锚定在选区下方；下方空间不足时自动切换到选区上方。面板位置和宽度限制在当前显示器工作区域内。面板宽度根据选区调整，同时设置合理的最小值和最大值。

面板按从上到下的顺序包含：

1. 源语言、截图翻译目标语言和当前状态。
2. 可选择的截图译文和“复制译文”按钮。
3. 快捷回复输入框。
4. 回复目标语言、翻译按钮、回复译文和“复制回复”按钮。

截图翻译目标语言默认为简体中文，用户可临时切换。快捷回复默认翻译成截图检测出的主要语言，也允许临时修改回复目标语言。快捷回复输入框按 `Enter` 发起翻译。

复制成功后短暂显示“已复制”，随后立即写入剪贴板、关闭覆盖层并返回原窗口。

## 7. 模型配置和请求协议

### 7.1 当前配置

首版只维护一套当前模型配置。默认预设为：

- 接口类型：OpenAI 兼容。
- 模型名称：`qwen3.7-flash`。
- 思考模式：关闭。
- 翻译随机性：低随机值。

用户可以在设置窗口直接修改：

- API 服务地址。
- API Key。
- 模型名称。
- 思考模式。
- Temperature。
- 最大输出长度。
- 请求超时时间。
- 额外请求参数 JSON。

“测试连接”会发送一次极小的实际请求，并明确提示可能产生少量 API 用量。它用于同时校验地址、密钥、模型权限和响应格式，而不是只做本地表单校验。

### 7.2 截图翻译请求

1. 从本次会话的原始冻结位图裁剪选区，避免重新截屏导致内容变化。
2. 保持 PNG 以保护小字清晰度；只有超过模型输入限制时才按比例缩小。
3. 将裁剪图片、目标语言和内置提示词发送给模型。
4. 请求默认携带 `enable_thinking: false`；用户开启思考模式后改用用户设置。

内置提示词要求模型：

- 自动识别截图中的主要语言。
- 翻译全部可读聊天内容。
- 保留用户名、行序和换行关系。
- 结合游戏语境处理缩写、俚语和口语。
- 不输出解释、分析过程或无关内容。
- 返回固定结构的 JSON，至少包含处理状态、源语言和译文。

### 7.3 快捷回复请求

快捷回复使用同一个当前模型。提示词要求模型将用户输入自然、简短地翻译成目标语言，适合游戏聊天，不添加解释。目标语言默认来自最近一次成功截图翻译检测到的源语言。

### 7.4 响应容错

客户端优先解析约定 JSON。如果模型返回 Markdown 代码块，则先移除代码块包装再解析。如果仍无法得到标准结构，则只在能够明确提取纯文本译文时降级展示；否则报告响应格式异常，不能将不确定内容当作成功译文。

## 8. 设置与本地数据

设置窗口约为 `820 × 600`，左侧为“常规、模型、关于”导航，右侧显示当前页面内容。

### 8.1 常规设置

- 截图快捷键，默认 `Ctrl + Alt + D`。
- 默认截图翻译目标语言，默认简体中文。
- 随 Windows 开机启动，默认关闭。
- 界面主题：跟随系统、浅色或深色，默认跟随系统。

快捷键通过按键录制控件输入。保存时尝试注册新组合；注册失败时显示明确字段错误并保留原快捷键。

### 8.2 模型设置

模型设置包含第 7.1 节中的全部字段。API Key 使用普通明文输入框，不做遮挡。所有配置项均可直接查看、编辑和保存，不依赖代码修改或隐藏配置文件操作。

### 8.3 关于页面

- 当前版本。
- GitHub 仓库入口。
- MIT 许可证入口。
- 开源依赖说明。

### 8.4 配置存储

全部配置统一保存在：

`%APPDATA%\ScreenshotTranslator\settings.json`

API Key 以明文保存在该文件中。应用不使用 Windows 凭据管理器。保存过程先写临时文件，再原子替换正式文件，以降低配置损坏风险。仓库只提供不含真实密钥的配置示例，并通过 `.gitignore` 排除本机配置与常见秘密文件。

## 9. 错误处理与隐私

错误优先显示在截图结果面板或对应设置字段内，避免打断游戏的系统弹窗。

- 缺少必要配置：不发起请求，提供进入设置的操作。
- `401/403`：提示检查 API Key、模型名称和服务权限。
- `429`：提示请求频率或额度受限，并提供重试。
- 超时、断网或服务端错误：保留当前选区，显示简短原因和重试按钮。
- 未识别到文字：显示“未识别到可翻译内容”，允许调整选区。
- 响应格式异常：说明模型返回无法解析，不展示不确定译文。
- 剪贴板写入失败：保持面板打开并提示重试。
- 配置文件损坏：备份损坏文件，恢复默认配置并打开设置窗口。

应用不将截图、用户输入、完整请求、完整响应或译文写入磁盘和日志。诊断日志只记录必要状态、错误分类和脱敏后的技术信息，不记录 API Key。应用不包含遥测。

## 10. 视觉与可访问性

界面采用克制的现代 Windows 工具风格，不复制参考软件的多余工具栏功能。

### 10.1 截图覆盖层

- 选区边框使用清晰的蓝紫色强调色，宽度约 2px。
- 八个控制点使用白色填充和强调色描边，并提供足够大的命中区域。
- 结果面板使用深色石墨背景、圆角和轻阴影。
- 状态变化在同一面板内完成，不通过多个弹窗堆叠。
- 仅使用统一的矢量图标，不使用 Emoji 充当功能图标。
- 避免持续、闪烁或影响游戏注意力的动画。

### 10.2 设置窗口

- 使用 `Segoe UI Variable` 和统一的 8px 间距体系。
- 输入项始终有可见标签，不只依赖占位文字。
- 保存按钮固定在右下角，仅在配置发生变化时启用。
- 字段错误显示在对应控件下方。
- 支持清晰的键盘焦点、可辨识的禁用状态以及足够的文字对比度。

## 11. 测试与验证策略

### 11.1 自动化测试

使用 xUnit 覆盖：

- 选区创建、移动、八点缩放和屏幕边界限制。
- 不同 DPI 下逻辑坐标与截图像素坐标的转换。
- 翻译工作流的加载、成功、失败、取消和过期响应。
- 模型请求结构、思考模式参数和响应解析。
- 配置默认值、保存、读取、校验和损坏恢复。
- 快捷键冲突处理。
- 日志脱敏。

真实百炼调用只存在于显式启用的手动集成测试中，API Key 通过本机环境变量提供，不进入仓库或默认 CI。

### 11.2 Windows 人工验收

- Windows 10/11 x64。
- 100%、125%、150% 和 200% 显示缩放。
- 主屏和副屏，确认只冻结鼠标所在显示器。
- 普通窗口和无边框窗口游戏。
- 默认及自定义快捷键。
- 调整选区后只展示最新结果。
- 复制后关闭覆盖层并返回原窗口。
- 断网、错误密钥、限流和超时。
- 设置重启后保留，包括明文 API Key。
- 重复启动不会创建多个托盘进程。
- MSI 安装、卸载和干净 Windows 环境首次启动。

### 11.3 验证原则

验证强度与变更风险匹配。开发过程中默认执行一次聚焦、足够的验证：先运行直接覆盖改动的测试，再根据影响范围决定是否运行更大测试集。小修复只补充或重跑与该风险直接相关的检查；只有跨模块修改、发布候选或风险明显扩大时才重复完整测试与人工验收。禁止为了形式而连续执行无意义的全量重复验证。

## 13. 验收标准

满足以下条件时，首版可以验收：

1. 安装后程序能单实例运行并常驻系统托盘。
2. 默认 `Ctrl + Alt + D` 能在普通窗口和无边框窗口场景冻结鼠标所在显示器。
3. 用户能创建、移动和八点缩放选区，选区改变后只显示最新翻译结果。
4. 默认千问配置使用 `qwen3.7-flash` 并关闭思考模式；用户能在设置中查看和修改全部模型参数及明文 API Key。
5. 截图能直接交给多模态模型，返回源语言和目标译文。
6. 用户能在结果面板输入快捷回复，并默认翻译成截图源语言。
7. 复制任一译文后覆盖层关闭、焦点返回原窗口，剪贴板内容可直接粘贴。
8. 常见配置、网络和模型错误不会导致程序崩溃，并提供可执行的错误提示。
9. 截图、输入内容、API Key 和译文不会进入日志；项目不包含遥测。
10. 自动化测试、目标 Windows 人工验收和 MSI 安装验证按第 11 节通过。
